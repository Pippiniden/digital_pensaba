### `js/cpu.js`（既定はオフ＝挙動は変わらない実験用スイッチ）
測定の結果、効果がなかったか有害だったものを残してある。消してもよい。
- `CPU_SPELL_GUARD`（false）: 回避・無敵の令呪を敵の宝具に合わせる（`cpuGuardEff`）。慎二入り4万試合で 49.1%、改善なし
- `CPU_SPELL_COSTK`（0）+ `CPU_SPELL_COSTPID`: 令呪1回＝行動1回分の期待ダメージを点数から引く。K=0.5〜4 のどれも勝率が下がった
- `CPU_SPELL_RESERVE`（false）/ `masterThreat` / `spellReserved`: 自分のマスターが次の一撃で倒れる位置なら最後の1画を防御用に温存。倒れる割合は2割減るが勝率はほぼ同じ
- `CPU_SPELL_EVK`（0）/ `spellKeepValue`: 上の期待値版（確率×損失×係数）。倒れる割合は35〜45%減るが勝率は約1ポイント
- `CPU_SPELL_BURN`（0）/ `CPU_SPELL_SETUP`（0）: 倒しきれない敵マスターへの大ダメージで相手の令呪を切らせる／次の令呪で仕留める布石の加点。**有効にすると特化型マスターは強くなる**（後述）。既定オフなので実戦CPUは使っていない
- `SPELL_MIN_BY`（{}）: マスターID別に最低点を上書き（比較用）
- `CPU_SPELL_KILL` は 0 / 1 を入れると片陣営だけ新ロジックにできる（A/B比較用）

### `js/engine.js`

## 2. 令呪まわりでわかったこと（マスターチーム、servants合計コスト10＋マスターコスト3、CPUは「つよい」先読みなし）

### 令呪1回で行動1回と釣り合う強さ（強制使用＝使える最初の機会に必ず使う）
| 効果 | 釣り合う強さ |
|---|---|
| 単体攻撃（敵1体） | 約130 |
| 全体攻撃（敵全体） | 約80 |
| 回復（味方1騎） | 約200〜250（頭打ち） |
| デバフ（攻撃ダウン・防御ダウン、敵全体・3T） | 約30 |
| 1T補助（攻撃アップ・防御アップ） | 60でも届かない |
| 敵マスターへのダメージ | 届かない（相手の令呪で防がれる） |

### 令呪が行動を使わない場合（`SPELL_FREE=1`）
どの効果も弱くても得になる（例: 単体100で 47%→55%）。1コストの重さは約 +5.5〜6.5%（コスト3対2が55%、4対3が56.7%）。攻撃アップ1T 40 の令呪3つで約 +4〜5%（≒0.7コスト）。

### 敵マスターへのダメージ
- マスターのHPは回復できないので、補助ダイスで削り続ける戦法は防御側CPUが令呪を温存しても止められない（防御の工夫は倒れる割合を減らすが勝率はほぼ動かない）
- 補助ダイスの3面が敵マスター攻撃、令呪「敵マスター300」を持つ特化型（コスト4）の目安: 令呪2つなら補助ダイス1面 60〜80、令呪1つなら 80〜100。100超は強すぎる
- 令呪の敵マスターダメージは 250〜300 が妥当（350以上は2回で全員倒せ、400は一撃になる）。ただし CPU が `CPU_SPELL_BURN/SETUP` を使わないと削りダメージ自体が使われず効果が出ない（勝率は令呪なしと同じ）

### マスタールール（`G.rule==='master'`）
- CPU が令呪を使う道は「16★払う即時発動」だけで、★の中央値は0。令呪は1試合あたり約3%しか使われない
- 令呪を宣言して次ターンに撃つ方式はどの点数でも勝率が下がった（宣言したターンの行動を飛ばされ、宣言中は令呪で守れないため）

## 4. 刹那の修正案（`docs/proposals/masters_setsuna_proposal.js`、未採用）
ユーザー希望: 「女性サーヴァントのみで構成した場合に勝率が53%を超えるくらい」。
- 女性のみ編成は、どのマスターでも約15ポイント弱い（切嗣 52→35、凛 65→52）。元の刹那も 36.8%。補助面の数値を倍率で変えるだけでは 36〜38% のまま
- 効いたのは令呪に「女性の味方にだけ NP +60」（`np`, `t:'ally_svt'`, `cond:{k:'trait',v:'女性'}`）を足すこと
- 修正案: 補助1番 攻撃時スター 4→2（女性+10）、補助3番 攻撃アップ 30→15、補助5番 攻撃時NP 15→8（女性+22）、令呪1に女性NP+60、令呪2は回復150→100＋女性NP+60、令呪3は変更なし
- 結果: 女性のみ **53.8%**、ランダム編成 約56%（元は 36.8% / 52〜53%）
- 注意: `atk` の `cond` は攻撃する相手を見る仕様（`condUse`）なので、味方の女性に限定できない。攻撃アップは下げただけ。ランダム編成でも約56%まで上がる（女性が1人入れば NP が効く）

## 5. 測定スクリプト（`tools/sim/`）
Node で動く。先頭の `root` は `tools/sim/` から `../../js/` を指す。マスターデータを差し替えたいときは環境変数 `MFILE`（未指定なら同フォルダの `newmasters.js`）。出力は標準出力（`mall.js` は第4引数にJSONも書く）。
| スクリプト | 用途 | 例 |
|---|---|---|
| `mall.js` | 全マスター総当たり（ルール別の勝率表） | `node mall.js mteam 4000 out.json` / `node mall.js master 4000 out.json` |
| `mx.js` | 1マスターの変種比較（`base` / `nospell` / `min6` / `free1` / `spellN`、`minN`=そのマスターだけ最低点上書き） | `node mx.js ssetsuna min6 4000` |
| `mx3.js` | 設定（`MIN` `K` `AGG`）ごとの全マスターの「令呪の寄与」（`L`=使う / `none`=使わない） | `MIN=4 AGG=max node mx3.js m_rin L 2500` |
| `mx4.js` / `mx5.js` | 刹那の設計案比較。`FEM=1` で女性のみ編成。`DES=s,m,spl`（倍率）／ `DESJ`（面・令呪の効果をJSONで差し替え） | `FEM=1 DESJ='{...}' node mx5.js ssetsuna L 3000` |
| `val.js` | 効果の種類×強さごとの損益（強制使用／通常CPU）。`FREE=1` で令呪が行動を消費しない | `node val.js single forced 1500` |
| `val2.js` | 任意の令呪セット同士の対戦。`FREE` `BURN` `MIN` | `node val2.js '[[{...}]]' null 2000` |
| `val4.js` / `val5.js` / `val6.js` | 敵マスターダメージ特化型の評価（`val5`=補助ダイスの攻撃面つき、`val6`=防御回数・マスター撃破率の計測つき） | `D=80 NSP=2 BURN=3 SETUP=3 node val5.js 300 1500` |
| `ab.js` | 同一編成を入れ替えて新旧ロジックを比較（陣営0だけ新ロジック） | `node ab.js mteam 5000` |

並列で回すなら `xargs -P`。20並列で1設定あたり1〜2分。出力ファイルは1ジョブ1ファイルにすること（同じファイルへの追記は行が混ざる）。

## 6. 測定の落とし穴（実際にハマったもの）
- 誤差: 3,000試合で約±0.9%（差を見るなら約±1.5〜2.8%）。1〜2ポイントの差は誤差。判断は3万試合以上か、複数条件で同じ向きに出たものにする
- `CPU_SPELL_KILL` / `SPELL_MIN_BY` などのスイッチは両陣営共通のグローバル。片側だけに効かせたいときは陣営番号（pid）で分ける（`0`/`1` を入れる）
- 女性のみの編成の比較は、基準（同じ女性のみ編成の他マスター）を必ず見る。女性のみ編成は全員約15ポイント弱い
- シェルでスクリプト引数の位置を間違えて出力JSONの書き込み先に入力ファイルを指定すると上書きされる
- テスト用のスモークで `C:\tmp_out.json`（`/tmp_out.json`）が残っている可能性がある。削除は権限の都合で自動では行えなかったので、見つけたら手動で消してよい

## 7. 次にやること（優先順）
1. **慎二・雁夜の令呪が使われない問題**。低コストマスターの令呪の点数を見直す（`max` 集計で点が低いまま）か、マスター別の最低点を設ける。`mx3.js` の寄与を指標に、全マスターで「使うほうが得」になる設定を探す
2. **凛の突出（約65%）**。補助ダイスの敵マスター攻撃面（100×2）と令呪（350/200/60）の合計が強い。数値を下げるなら `masters.js` 側で
3. **令呪の費用ルールを決める**: 現行は「行動1回を消費」。`SPELL_FREE` の測定では、消費しないとマスターが強くなりすぎる（単体400で78〜84%）。決めたら `RULESETS.mteam` へ移し、`SPELL_FREE` を整理する
4. **敵マスターへのダメージの扱い**: `CPU_SPELL_BURN` / `CPU_SPELL_SETUP` を既定にするか。既定にしないと、敵マスター特化の令呪・補助ダイスがCPUでは使われない（効果が実戦に出ない）。有効にした場合、マスター特化型は 57〜68% に上がる
5. 刹那の修正案を採用するか。採用するなら `docs/proposals/masters_setsuna_proposal.js` の `ssetsuna` を `js/masters.js` に反映し、エディタの検証（大警告・小警告）が通るか確認する（令呪の数値や効果が泥ペンマスシートの目安から外れる可能性）
