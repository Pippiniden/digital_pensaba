# FGO の効果・状態異常 調査レポート（実装候補のまとめ）

2026-11-23 作成。FGO に出てくるスキル効果・状態異常と、このゲームの効果（`FX`、js/rules.js）を比べ、
「まだ無くて、入れられそうなもの」を難しさ順にまとめました。
FGO 側の細かい数値・仕様は攻略サイト頼みなので、**このゲーム向けの案**として読んでください（FGO と完全に同じにする必要はありません）。

---

## 1. まとめ

- このゲームはすでに FGO の主な効果をほぼ持っています（毒・やけど・延焼・スタン・魅了・恐怖・封印・回復無効・強化無効・即死・ガッツ・回避／無敵／必中／無敵貫通・特攻／特防 など 80 種以上）。
- **すぐ入れられるもの（A）**：蝕毒、弱体耐性アップ、HP回復量アップ／ダウン、クリティカル威力ダウン、宝具被ダメージ-、行動不能の種類（石化・拘束・睡眠）、混乱。
  どれも「既存の効果をまねて 1〜数行」で済みます。
- **設計を決めてから（B）**：呪厄（いまの「呪い」が FGO の呪いと別物なので先に整理が要る）、攻撃時に弱体を付ける、戦闘不能時に発動、HP が減るほど強くなる（背水）、○ターン後に発動。
- **このゲームに合わない（C）**：オーバーチャージ、スター集中度、クラス相性系 など。

いちばんのおすすめは **蝕毒**（延焼の毒版。ほぼ 1 行）と **弱体耐性アップ**（弱体耐性ダウンの逆。今は強化版が無い）です。

## 3. A：すぐ入れられるもの

> **2026-11-23 実装済み**（キー名）：蝕毒 `erosion` / 弱体耐性アップ `debuffRes` / HP回復量アップ `healUp`・ダウン `healDown`（±%）/
> クリティカル威力ダウン `critPowDown` / 宝具被ダメージ- `npDef` / 石化 `petrify`・拘束 `bind`・睡眠 `sleep`（攻撃でダメージを受けると解ける）/ 混乱 `confuse`（値＝行動不能になる出目、既定3）。
> 行動不能の判定は engine.js の `DISABLE_FX` にまとめた。下は実装前に書いた案（実際の仕様はコードと `FX_HELP` が正）。

効果を 1 つ足すときの手順（AGENTS.md の「New effect kind」）：
① `FX` ＋ `FX_GROUPS`（rules.js） ② engine.js で効果を働かせる ③ `fxText`（common.js） ④ `FX_HELP`（guide.js）
⑤ `cpuSkillScore`（cpu.js。無いと CPU は使わない） ⑥ 必要なら `checkEffs` ⑦ 値があれば tools/llm-pack.js の `VAL` → `node tools/llm-pack.js`
さらに tools/skill-waste.js の `WASTE_NOW` / `USEFUL` に 1 行。

### 3-1. 蝕毒（しょくどく）★おすすめ

- **FGO**：毒のダメージを増やす弱体。毒と一緒に付けて使う（例：毒の刃のように毒＋蝕毒を同時に付与）。
- **案**：`erosion:{name:'蝕毒',buff:false}` … 付いている間、**毒のダメージ2倍**。延焼（`spread`、やけど2倍）とまったく同じ形。
- **直す場所**：engine.js の `endPhase()` の毒の行（今は `ps=top('poison')`）に `*(has(u,'erosion')?2:1)` を付けるだけ。
- **CPU**：相手に毒が付いている（または同じスキルで毒も付ける）ときだけ点を付ける。延焼の点の付け方をまねる。
- **skill-waste**：毒が付いていない相手に付けた＝無駄、として数える。
- 値つき（毒+x）にしたい場合は `val:true` にして `ps+=合計` にする手もある。まずは延焼とそろえて「2倍」がわかりやすい。

### 3-2. 弱体耐性アップ ★おすすめ

- **FGO**：自分が受ける弱体の成功率を下げる強化（よくある防御スキル）。
- **今**：弱体耐性**ダウン**（`debuffResDown`、判定ロールを N+x）はあるが、アップが無い。
- **案**：`debuffRes:{name:'弱体耐性アップ',buff:true,val:true}` … 受ける**確率つき**の弱体の判定ロールを N-x にする（「必ず」の弱体には効かない＝ダウンと同じ扱い）。
- **直す場所**：engine.js の `applyEffs` 内、`debuffResDown` を見ている所（`const rd=…`、`need=…` の計算）で、同じように `mods(t,'debuffRes')` を引く。回数制なら同じく `consume`。
- **バランス**：「ロール6以下（必ず）」は防げないので強すぎない。精神異常だけに効く版（`mental` 限定）も vs 指定で作れる。

### 3-3. HP回復量アップ／ダウン

- **FGO**：受ける回復量が増える強化／減る弱体。
- **案**：`healUp:{name:'HP回復量アップ',buff:true,val:true}`、`healDown:{name:'HP回復量ダウン',buff:false,val:true}` … 受ける回復を **+x / -x（固定値）** か **±x%**。このゲームの数値は固定値が多いので、`atkPct` のように % 版にするか固定値にするかを先に決める。
- **直す場所**：`applyOne` の `case 'heal'`（今は回復無効のチェックがある所）と、ターン開始時の `regenHp` の回復の所。2 か所で同じ計算を使う小さな関数を作るとよい。
- 回復無効（`healBlock`）との違い：止めるのではなく減らす、なので弱めの弱体として使いやすい。

### 3-4. クリティカル威力ダウン

- **FGO**：クリティカルのダメージを下げる弱体。
- **案**：`critPowDown:{name:'クリティカル威力ダウン',buff:false,val:true,color:true}` … `critPow` の逆（クリティカルの増加量 -x、0未満にはしない）。
- **直す場所**：`critPow` を読んでいるダメージ計算（`dmgMods` / `resolveDamage` まわり）で引く。`critMult`（倍率指定）のときの扱いだけ決める。

### 3-5. 宝具被ダメージ-（宝具への防御）

- **FGO**：宝具ダメージだけを減らす・防ぐ系の強化がある。
- **案**：`npDef:{name:'宝具被ダメージ-',buff:true,val:true}` … 宝具の 1 ヒットごとのダメージ -x。`def` と同じ計算で、宝具のときだけ働く。
- **直す場所**：`resolveUlt` のダメージ計算（`npPowDown` を引いている所の近く）。`ignoreDef`（被ダメージ減少無視）で無視されるかを決める。

### 3-6. 行動不能の種類（石化・拘束・睡眠）

- **FGO**：スタン以外にも行動不能の種類がいくつかあり、精神異常に入るもの・入らないものがある。
- **今**：行動不能は `disabled = u=>has(u,'stun')||has(u,'charm')`（engine.js 133 行）だけで判定している。
- **案**：`petrify`（石化）、`bind`（拘束）、`sleep`（睡眠、`mental:true`）を足し、`disabled` に並べる。
  睡眠だけ「ダメージを受けたら解ける」にすると個性が出る（`dealDamage` で消す）。
- **意味**：見た目・名前のバリエーションと、「精神異常無効で防げる／防げない」「種類指定の弱体解除・弱体無効」の違いが作れる。
- **注意**：スタン系は強いので、令呪の強すぎ注意（`MSHEET.spell.strong`）と `refLimits` にも同じ制限を足す。

### 3-7. 混乱

- **FGO**：毎ターン一定確率で行動できなくなる精神異常（恐怖も FGO ではこの形）。
- **案**：`confuse:{name:'混乱',buff:false,mental:true}` … 行動回数決定フェイズで 1d6 を振り、`v` 以下なら行動回数 0（そのターンは行動不能）。値なしなら「3 以下」など既定値。
- **直す場所**：行動回数決定（engine.js 1400 行あたり、`fear` / `actsDown` を見ている所）。ログとロール演出（`rollFx`）を足す。
- いまの恐怖（行動回数-1）とは別物なので並べて使える。

### 3-8. CPU（つよい）の使いどき（シミュレーションで決定・2026-11-23）

つよい同士・同じ編成のミラー戦。全キャラのスキル1をその効果だけのスキルにし、片方だけ案の判断で使う（各4000試合・先読みなし・誤差 ±1.5%）。
数字は「案の側」の勝率（相手は実装前の判断）。採用した判断は cpu.js の `cpuEffScore` にコメントつきで入れてある。

| 効果 | 採用した判断 | 主な結果（チーム） |
|---|---|---|
| 蝕毒 | 毒の付いた敵がいる（同じスキルで毒も付ける）ならすぐ | 66.5%（使わない 46.2%） |
| HP回復量アップ | 減った味方がいて、回復の手段があるとき | 63.7%（すぐ 61.3%・HP70%未満 60.5%） |
| HP回復量ダウン | 回復の手段を持つ敵がいれば先に | すぐ 69.6%（敵が減ってから 50.5%） |
| 宝具被ダメージ- | 敵が宝具を撃てる（NP100%）とき | 56.9%（すぐ 44.9%） |
| クリティカル威力ダウン | 敵のスター6個以上 | 52.1%（すぐ 50.8%） |
| 睡眠 | スタンと同じ（すぐ）＋寝ている敵は倒せないなら殴らない | 51.5%（狙いを変えないと 49.4%） |
| 混乱 | チーム：倒れそうなときだけ（旧判断のまま）／1騎のルール：すぐ | チーム すぐ 48.0%／シンプル すぐ 54.2% |
| 弱体耐性アップ | 確率つき弱体を持つ敵がいれば小さく加点 | どの案も 50〜51%（差なし） |
| 石化・拘束 | スタンと同じ（変更なし） | スタンの案比較は差なし |

確認（新しい判断 vs 「使わない」）：チーム 28.6〜46.3%、シンプル 38.0〜49.4% で、どれも新しい判断の方が勝つか同等。

## 4. B：設計を決めてから入れるもの

| FGO の効果 | 何が問題か | 案 |
|---|---|---|
| **呪厄**（呪いのダメージアップ） | このゲームの「呪い」(`curse`) はダメージを出さない（被弾 NP 封印）。FGO の呪い＝毎ターンダメージに当たるのは `drain`（HP減少） | ① `drain` 用の倍化として「呪厄＝HP減少2倍」にする（実装は蝕毒と同じ 1 行）。② 名前の混乱を避けたいなら、`drain` の表示名を見直してから入れる。※ 既存データの `curse` の意味は変えない |
| 攻撃時に弱体を付ける（攻撃時に確率でやけど など） | 効果の中に別の効果を持つ形が今は無い | `onAtkEff:{...,eff:{k,t,v,turns,chance}}` のように子の効果を持たせ、`onAtkNp` と同じ所で発動。エディタ・検証・CPU の点も子の効果を見る必要あり（大きめ） |
| 被ダメージ時に弱体を付ける | 同上 | `counter` の所で発動する子効果版 |
| 戦闘不能時に発動（倒れたとき味方の NP+ など） | `retreat()` に発動点が要る。`flushKo()` の順番に注意 | `onOut` 強化（子効果）。ガッツで踏みとどまったときは発動しない |
| 背水（HP が減るほど攻撃力アップ） | 今は条件 `hpBelow`（○%以下）の段階式のみ | `atkLowHp`：失った HP の割合 × v で攻撃ダメージ+。`dmgMods` で計算するだけなので実装は軽いが、CPU の評価と数値の目安が要る |
| ○ターン後に発動（時限式の即死・自分にスタン など） | 「切れたときに発動する」仕組みが無い | 効果が切れる処理（ターン減少）で `onExpire` の子効果を発動。宝具後の自分スタンなどにも使える |
| 毎ターン NP 減少 | `regenNp` に負の値で代用できるか要確認（NP減少無効との関係） | 代用できればデータだけで済む。無理なら `npDrain` を `drain` と同じ所に足す |
| 毒・やけどの重ねがけ | FGO は重なる、このゲームは最大値。仕様変更なので全キャラの強さが変わる | 入れるなら `RULES.dotStack` のような切り替えにして、`tools/ref-check.js` で勝率を測る |

## 5. C：このゲームに合わないもの（入れない）

- **オーバーチャージ**（NP 200%/300% で宝具が強くなる）：NP の上限が 100 で、宝具の仕組みが違う。
- **スター集中度**：スターは陣営で共有し、レベル表でクリティカルを決める方式なので「誰にスターが集まるか」が無い。
- **クラス相性・クラス特攻／特防**：このゲームはクラス相性なし（フレーバー）。属性（traits）の特攻で十分代わりになる。
- **チャージ（敵のゲージ）・ブレイクゲージ**：敵専用の仕組みで、対人戦に合わない。
- **パーセントのガッツ・最大HP比のダメージ**：ほかの数値がすべて固定値なので、入れると基準（`UNIT_REF`）が崩れやすい（`dmg` の `max` のような限定的なものは既にある）。

---

## 6. 進め方の案

1. **蝕毒** と **弱体耐性アップ** を先に入れる（小さく、既存の効果の写しで済む）。
2. 続けて **HP回復量アップ／ダウン**、**クリティカル威力ダウン**、**宝具被ダメージ-**。
3. 行動不能系（石化・拘束・睡眠・混乱）は強いので、令呪の上限・`refLimits` もあわせて入れる。
4. どれも入れたあとに `node tools/check.js`（止まり・NaN の確認）と `node tools/skill-waste.js`（CPU が無駄に使っていないか）を回す。
5. B の「子効果を持つ効果」（攻撃時に弱体・戦闘不能時・時限発動）は仕組みを共通にできるので、まとめて設計する。
