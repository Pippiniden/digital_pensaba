# ファイル配置の詳細 (AGENTS.md §2 の詳細版)

ファイルの役割を詳しく知りたいときだけ読む。コードが正。

| Path | Role |
|---|---|
| `index.html` | Game page shell. `#titlebg` (title-screen night sky, a `position:fixed` layer outside `#app`, shown only on `body[data-screen="mode"]`; filled once by `initTitleBg` in game-ui.js with star layers, the spinning magic circle and mist, so `render()` never restarts their animations), `#app` (render target), `#fx` (effects layer), and the header whose buttons live in `#menu` (collapsed behind `#menubtn` ☰ at ≤860px; open state is `UI.menu` → `body.menuopen`) |
| `editor.html` | Editor page shell. Three columns: `#list` `#form` `#side` |
| `js/rules.js` | **Rule definitions**: terms `TERMS`, numbers `RULES`, effect kinds `FX`, targets `TARGETS`, line kinds `LINE_KEYS`, classes, image settings |
| `manifest.webmanifest` + `sw.js` + `img/pwa/` | **PWA**. index.html links the manifest and registers `sw.js` (https or localhost only). The service worker is stale-while-revalidate for same-origin GETs (cache `pensaba-duel-v2`; a change shows on the 2nd load), cross-origin (Web fonts) is not cached. Icons: 192 / 512 / maskable 512 |
| `js/units.js` | **Default character data** `DEFAULT_UNITS` (same format the editor's "export units.js" produces) |
| `presets/original/` | **Not loaded by the game.** A frozen copy of the canon data (9 servants, 7 masters, their images) in the same export format, for people who copy this engine and want to drop the canon data in (see its README.md). `js/` data stays as the live data |
| `js/masters.js` | **Master data** `DEFAULT_MASTERS` for the master rules (rules-spec.md の Master rule / Master team battle). Currently 7 **test-only** canon masters (遠坂凛 C5 … 間桐雁夜 C0), expected to be replaced/removed. Same format the editor's "masters.js を書き出し" produces (`mastersToJS`) |
| `js/common.js` | **Shared by game and editor**: data normalization, validation, load/save/export, HTML/string builders (cards, effect descriptions) |
| `js/engine.js` | **Game logic**: state `G`, `ACTIONS`, damage/effect resolution, turn flow |
| `js/cpu.js` | CPU brain. `cpuDecide()` only returns the next single move. Difficulties in `CPU_LEVELS` (`easy` / `normal` / `hard` つよい / `expert` 超つよい) |
| `js/fx.js` | Visual effects (speech bubbles, damage numbers, ultimate cut-in, phase banners, pencil-roll animation, attack-card zoom). Plays `FXQ` in order |
| `js/cutin.js` + `css/cutin.css` | **Noble Phantasm cut-in**, shared by the game (`showCutin` in fx.js) and the editor preview. `cutinStageHTML(d,ult,{hold})` builds a 16:9 stage (`.ct`, all sizes in cqw/cqh); `cutinLayout(stage,ult)` fills ruby + name and fits them (must be in the DOM; `cutinLayoutWhenReady` re-measures after web fonts load); `cutinIssues` turns the result into editor warnings. Name fitting never changes font-size: it scales with `transform` around the glyph's bottom-left, so the name's bottom edge never moves; `ult.br` picks auto / one line / two lines (see data-model.md). Length `CUTIN_MS`, fitting knobs `CUTIN_NAME`. Also used for master 令呪 (`useSpell` emits `{t:'cutin',col:'Y',top:'令呪発動'}`; `.ct.Y` = provisional gold). Speed setting shortens it via `cutinScale()` in fx.js (速い 0.7× / 最速 0.5×, animations get `playbackRate`). Band, lightning edges and name strip live inside one rotated `.ct-band` so their angles always match. Light particles = `.ct-pimg`, the seamless image `UI_IMG.cutinParticles` scrolled inside `.ct-fill` beneath the face close-up (opacity .2, 33 s per loop). Thin letterbox bars `.ct-lb` (8cqh, above the standing art) hide heads cut off at the top; `宝具発動` sits centred in the top bar; per-unit art position = `fit.cut` (`--cx/--cy/--cz`). Motion = quick entry (`--ix/--iy`) + linear drift until the end (`--dx/--dy/--ds`, registered with `@property`) |
| `docs/cutin-np-sample.html` | Stand-alone tuning sample for the cut-in (toggles, sliders, export of tweaks as text). Not loaded by the game; port settled values into cutin.css |
| `js/guide.js` | Tiered rules guide + status-effect help (`rulesGuideHTML` / `statusGuideHTML`, texts in `FX_HELP`; **add a line there when you add an FX key**). Shown at the bottom of the top menu and in the tutorial. Loaded before game-ui.js |
| `js/game-ui.js` (mode screen) | `modeHTML` is a menu tree driven by `UI.nav` = `{s:'top'\|'quick'(step rule→level)\|'local'\|'tutorial'\|'settings'\|'zukan'}` (UI-only; `uiAct` `nav`/`navNext`/`navBack`). `'zukan'` (図鑑) is its own screen (`body[data-screen="zukan"]`, `zukanHTML`): tabs `UI.ztab` = `'svt'`/`'master'`, reuses the setup roster filter (`rosterList` skips "編成できるものだけ" outside setup) and `UI.setupView` for the right-hand detail (`zukanDetailHTML` = `unitDetailHTML` + セリフ by scene); on ≤860px a tap opens the `UI.sinfo` modal instead. No game state is touched. Settings: speed (`pencilduel.speed`, read by `newGame` via `window.SPEED_PREF`) and link confirmation (`pencilduel.linkConfirm`). `restart` returns to top unless the button has `data-keepnav` (P1 setup "← 戻る") |
| `js/game-ui.js` | Game screen rendering (`render`) and input (click handling) |
| `js/editor.js` | Editor rendering, input, auto-save. Two tabs in the left column (`tab` = `'units'` / `'masters'`, remembered in `pencilduel.editorTab`): `list()` / `selIdx()` / `cur()` follow the tab, and the header buttons (apply / unapply / export / JSON / import / reset) act on the current tab. Master sheet (泥ペンマスシート): `MSHEET` / `SPELL_TPL` in rules.js, `masterSlot` / `masterRef` / `masterRefText` / `checkMasterSheet` in common.js (called from `validateMasters`). Issue levels are `error` (blocks apply) / `big` 大警告 (breaks a sheet rule: HP outside cost×100±100, 補助4番 empty, more filled faces than the cost, forbidden effects NP+/無敵/スタン/即死/回避 without 1回/魅了 other than 敵単体・ロール3以下, >3 same-kind effects, >1 limit-1 or >2 limit-2 effects) / `warn` 小警告 (off-guideline: HP step, too few faces, value above the reference, limit effect outside 4番); Missing/too-few speech lines are their own level `line` (セリフ, counted separately from `warn`). In the editor every non-error issue has an 無視 button (`issBoxHTML`, `acked` in localStorage `pencilduel.ackIssues`, key = tab|character id|message, so changing the content brings the warning back); ignored ones are listed under 「無視した警告」 with 戻す. `effRow` shows the reference line (`.effref`) under each 補助 effect and each 令呪 has a 汎用令呪 template select (`data-spl`). `masterTpl(cost)` (common.js) builds the cost-appropriate HP + 6 faces (no sheet warnings); the master form's "このコストのテンプレを適用" button applies it and `newMaster()` starts from cost 4 with that template plus three template 令呪. Master tab: `renderMasterForm` / `renderMasterSide` / `newMaster` (effects use ctx `'master'`; 補助 faces hide the turns input) |
| `js/sim.js` | **Balance simulation core**: `simGame(picks,rule,handicap,mpicks,level)` plays one headless match (both sides CPU at `SIM_LEVEL` = `'hard'` (つよい) **without lookahead** (`CPU_LOOKAHEAD=false`; the balance lab can pass `level:'hard+'` = `SIM_LEVEL_LOOK` for hard *with* lookahead, which `simGame` handles by setting `CPU_LOOKAHEAD` per game — about 50× slower per game; the editor's balance dialog is always without), draw after `SIM_TURN_LIMIT` turns). Simple rule: `simPair(a,b,n,handicap)` aggregates n games from `a`'s side. Team rule: `simTeam(t,n,pool,full)` gives `t` random allies (cost ≤ `costCap`, as many units as possible; `full` = only teams at exactly `costCap`) against a random team **without `t`** with the **same total cost and size** (`simTeamPlan`), and breaks the win rate down by ally / enemy unit / team cost |
| `js/sim-worker.js` | Web Worker that `importScripts` rules → units → common → engine → cpu → sim with a no-op `render()`, sets `UNITS` from the posted draft and posts one `{t:'pair',r}` per matchup (simple) or per target unit (`rule:'team'`), then `{t:'done'}` |
| `balance.html` + `js/balance.js` + `js/balance-worker.js` + `css/balance.css` | **Developer-only balance lab** (not linked from the game; only the editor header has a "検証ラボ" link). Data source switch (公開データ = `js/units.js`/`js/masters.js` / ブラウザに反映済み = `pencilduel.units`+`masters` / エディタの下書き = `pencilduel.editorDraft`+`masterDraft`), rule tabs (`team` / `mteam` / `simple` / `master`) and three analyses: **rank** (every legal team plays `k` random opponents → team ranking + per-unit / per-master average win rate, win-rate matrix for simple), **team** (one specified team vs all/sampled teams, or a direct duel of two specified teams), **master** (master strength: both sides use the *same* servant team and only the master differs, no handicap; master×master matrix, master×servant matrix for the master rule). `plan()` builds the matchup list (`enumTeams`, `planRank/planTeam/planMaster`); `startRun()` feeds them to a pool of `balance-worker.js` workers (each runs `simMatchup` from sim.js, which alternates sides every game and reports from A's view); `resRank/resTeam/resMaster` aggregate. Master analysis in the team-size rule (`mteam`) has a per-master colour focus (`B.mcol` = {masterId: 'R'|'B'|'G'}, `B.cmin` default 7, UI `mcolHTML`): `enumTeams` (rank / team views) only pairs a focused master with servant teams meeting its condition, and in `planMaster` a pair that includes a focused master only uses servant teams whose pre-ascension command faces of that colour (`colorFaces`) total ≥ `cmin` (when both are focused, a team meeting either master's condition is enough; pairs with no such team are skipped and counted in `skip`). Exclusions share `pencilduel.simExclude` with the editor dialog (+ `pencilduel.simExcludeMaster`); settings are remembered in `pencilduel.balance` |
| `js/editor-sim.js` | Editor's "バランス検証" dialog (`#simdlg`): options in `SIM` (`rule` simple/team, target, range/handicap for simple, `full` for team), starts/terminates the worker. Simple: per-opponent table or all-vs-all ranking + win-rate matrix. Team: `simTeamResultHTML` (one unit: summary + ally / enemy / team-cost tables; all: ranking). "検証から外す" chips (`SIM.excl`) drop special characters (e.g. メディア, whose NP gain is unusual) from opponents and all-vs-all; the selected character is still tested as the target |
| `css/base.css` | Shared styles (CSS variables, header, cards). `--lattice` = the faint diagonal grid layered first in every blue panel background (`background:var(--lattice),linear-gradient(160deg,…)`); new panels should do the same. `.skl` / `.sklb` = the detail view's skill / NP / 令呪 / master-face blocks built by `sklBlockHTML(no,name,lines,{cls,note})` (common.js): a header row (badge + name + note) and the effects one per line from `effLines` |
| `css/buttons.css` | **All button looks** (loaded last by index / editor / balance). Roles: default = secondary (navy + thin gold frame), `.primary` / `.gbtn.go` = the one gold-filled "go" button per group (placed rightmost), `.back` / `.ghost` / header = quiet, choices (`.seg`, menu `.gbtn`, `.rchip`, editor chips) show the selected state as gold frame + gold text (never a gold fill), tabs (`.rtabs` / `.edtabs` / `[role=tab]`) = text + gold underline. Sizes `.small` / default / `.big`. Principles in `docs/ui-design.md`; do not add button colours or shapes elsewhere |
| `css/game.css` / `css/editor.css` | Per-screen styles |
| `img/units/` | **Character images by id**: `{id}.webp` (face), `{id}_card.webp` (command card, optional). Names/extension set by `IMG_DIR` / `IMG_EXT` / `IMG_CARD_SUFFIX` in rules.js |
| `img/classes/` | Class icons (webp) / `img/placeholder/` placeholder images (face.webp / card.webp) / `img/ui/` magic circle and `grail.webp` (the Holy Grail on the ascension card), `title-bg.webp` (title background for landscape screens, 16:9, ideally 2560×1440) / `title-bg-sp.webp` (portrait screens, `max-aspect-ratio:1/1`, about 1080×2340); keep the centre dark and empty because the title, showcase, menu and magic circle sit there (paths in `UI_IMG`) |
