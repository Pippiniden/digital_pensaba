# 「〜したい」→ 編集箇所 (詳細表)

| I want to… | File / place |
|---|---|
| Add or tune a character (numbers / skills / lines) | `js/units.js` (or edit in the editor, export, and replace). `id` is half-width alphanumerics, `_`, `-`, unique. Cost ≤ `RULES.costCap` |
| Add or change a rule variant (party size, crit method, win conditions) | `RULESETS` in `js/rules.js` → `ruleset()` checks in `engine.js` (`resolveCommand` crit, `checkWin`, `applyHandicap`, setup ACTIONS) → `critInfo` / `setupHTML` / `modeHTML` in `game-ui.js` |
| Balance numbers (NP amounts, chains, crit bonus, action-count table, etc.) | `RULES` and `CRIT_TABLE` in `js/rules.js` |
| Change terminology / display names | `TERMS` in `js/rules.js` |
| Add a class | `CLASS_ICONS` in `js/rules.js` (icons in `img/classes/`). Names not in the list also work and get `extra.webp` |
| Add a new line scene | `LINE_KEYS` in `rules.js` → call `say(u,'newKey')` in `engine.js`. The editor and export read `LINE_KEYS` automatically |
| **Add a new effect kind** (e.g. a new status) | ① define it in `FX` in `rules.js` and add it to a category in `FX_GROUPS` ② apply it in `engine.js` (instant effects in `applyOne`; lasting effects wherever they are read via `mods()`: `resolveCommand` / `resolveUlt` / `blocked`, etc.) ③ display text in `fxText` in `common.js` (the `default` branch uses `FX[k].name`) ④ add a score in `cpuSkillScore` in `cpu.js` ⑤ add validation to `checkEffs` in `common.js` if needed. The editor's choices are generated from `FX` automatically |
| Add a new effect target | `TARGETS` and `TGT_BY_CTX` in `rules.js` → `resolveTargets` in `engine.js` |
| Change turn flow / phases | `ACTIONS` plus `beginTurn` / `endPhase` / `toTargetPhase` in `engine.js`. On the display side: `promptHTML` / `stageHTML` (`stepNo`) / `ctlHTML` in `game-ui.js`. Update `cpuDecide` in `cpu.js` to match |
| Damage calculation / crits / chains | `resolveCommand` (normal), `resolveUlt` (ultimate), `resolveDamage` (chains), shared modifiers in `dmgMods` in `engine.js`. The CPU's estimate `estDamage` (cpu.js) reuses `dmgMods` |
| Add a new ACTION (operation) | Add it to `ACTIONS` in `engine.js` → a button with `data-a="name"` in the UI → `cpuDecide` if the CPU uses it. To accept it after the game is decided, add it to the allow-list inside `act()` in `engine.js`; to let it be pressed during the CPU's turn, add it to `FREE_ACTIONS` in `game-ui.js` (two lists with different purposes) |
| Make the CPU smarter / weaker | `js/cpu.js` (`level` is a key of `CPU_LEVELS`: `'easy'` / `'normal'` / `'hard'` / `'expert'`; `easy` uses the deterministic pseudo-random `rnd01`). Mode-screen buttons are generated from `CPU_LEVELS`. Strategy findings: focus the most dangerous (high-damage) enemy rather than the weakest; killing is not worth prioritising because each KO gives the enemy's survivors +1 action; avoid pushing a surviving enemy's NP to 100 |
| Game screen layout / look | `js/game-ui.js` (HTML generation) + `css/game.css`. The battle screen always fits the viewport with no scrolling (`.battle` is `100%` high, field rows `minmax(0,1fr) auto minmax(0,1fr)`, lane height `--lh` scales with `vh`). Each `.svt` is a size container (`container:svt/size`, content in `.svin`); the `@container svt` rules at the end of game.css switch it to a vertical card when narrow (aspect ≤ 1), hide `.sks` when ≤150px high and `.fxs` (replaced by the `.pfx` ▲▼ counts) when ≤200px. Hidden skills are reached through the ⓘ detail modal, which holds the usable skill/ultimate buttons (`.udops`; using one closes the modal); `.canskill` makes ⓘ glow when skills are usable. Setup / mode screens still scroll on small screens |
| Noble Phantasm cut-in look / name fitting | `css/cutin.css` + `js/cutin.js` (shared with the editor preview `cutinEdHTML` / `ctUpdate` / `ctMeasure` in editor.js). Try changes in `docs/cutin-np-sample.html` first |
| Effects (bubbles, numbers, cut-in, phase banners, roll, attack card) | Emit from `engine.js` (`fxEmit` / `say` / `phaseFx` / `rollFx`), play in `fxPlay` in `js/fx.js`; wait times in `FX_WAIT`; CSS in the "演出" section of `game.css` |
| Character select: sort / filter | `UI.roster` + `ROSTER_SORTS` / `rosterList` / `rosterFilterHTML` / `rosterTilesHTML` in `game-ui.js`. Field changes (`data-uif`) only redraw `.roster` (`redrawRoster`) so the search box keeps focus |
| Result screen (details) | `resultHTML` + tabs `RTABS` (`UI.rtab`: 概要 / サーヴァント別 / ダメージ推移 / バトルログ) in `game-ui.js`. Data recorded by the engine in `G.stats[uid]` (`st(u)`: dealt / taken / maxHit / kills / attacks / crits / ults / skills / blocked), `G.tl[turn]=[p0,p1]` damage dealt per turn, `G.chains[pid]` (R/B/G/brave), `G.starsGen[pid]`. All damage goes through `recDmg(src,u,real,raw,ko)` from `dealDamage` / `masterHit`; pass `{att}` or `{src}` so it is credited (DoT and the master-down cascade have no source). MVP = top `dealt` on the winning side |
| End-of-game timing | `fxNext` in `fx.js`: when the queue empties with `G.phase==='over'`, `UI.endReady` (shows the rematch / result buttons in `promptHTML`) turns on after the VICTORY banner fades, then the result modal opens |
| Auto-advance rules | `autoMove` / `hasSkillChoice` in `js/game-ui.js` |
| Command card look / shared assets | `cmdCardHTML` / `cardLayers` in `common.js`; asset paths in `CARD_LAYERS` in `rules.js`. The frame is pure CSS in `base.css` ("コマンドカード"): everything is sized in `cqw` (the `.ccard` is a size container, so the card looks the same at any width; only its own corner radius is `%`), `::before` = edge tint / bottom band / gold line / light streaks, `::after` = gold outer ring, `.cc-ft` span = inner line + diamonds; `.sm` drops the fine details; a `CARD_LAYERS` frame image (`.hasframe`) hides all of it. Brightness is tuned with `--ccv-*` at the top of that block (made with the sliders in `docs/card-frame-v2.html`, which is a stand-alone sample — keep it in sync if you change the look). The ascension (ASC) card shows `UI_IMG.grail` (`.cc-grail`, `.hasgrail` in base.css) |
| Balance testing (simple-rule and 3v3 auto matches) | Rules of a match: `simGame` in `js/sim.js` (runs on the real engine/CPU, so rule changes apply automatically). Dialog / options / tables: `js/editor-sim.js` + "バランス検証" in `css/editor.css`. Needs the page served over http (Workers don't load from `file://`) |
| Editor form / preview | `js/editor.js` (`renderForm` / `effRow` / `renderSide`) + `css/editor.css`. Effects are picked in two steps, category → kind (`.effgrp` select, `data-act="effGrp"`); categories come from `FX_GROUPS` in rules.js (`fxGroups()` puts any unlisted FX key under その他) — **add new FX keys to a group there**. Traits: `data-t="tags"` input + `#traitlist` datalist (`allTraits()`); skill / face speech: `ownLineIn` (`data-t="optlines"`, removes the field when empty) |
| Data validation rules (errors / warnings) | `validateUnits` / `checkEffs` in `common.js` |
| **Add a new field to characters** | `normalizeUnit` in `common.js` (otherwise it is dropped) → `unitsToJS` (export) → `newUnit` and `renderForm` in `editor.js` → `validateUnits` → existing data in `units.js` |
| Colors / fonts / shared components | CSS variables in `css/base.css` |
