# AGENTS.md — Pencil Duel: Spec and Structure Guide (for AI agents)

Read this file before touching the code, then use the "I want to… → where to edit" table (§7) to pick your entry point.
It was written from the code (`js/*.js`). If you find a mismatch, the code is the source of truth — fix this file too.

## 1. What this is

- A browser game, **PENCIL DUEL**: a 1v1 party battle played with six-sided pencils as dice (Fate fan-made style, Japanese UI), plus the **Pencil Editor** for editing character data.
- Static HTML + plain JavaScript. **No build, no npm, no framework, no tests.** No ES Modules either: files share globals through `<script>` load order.
- Run: `python -m http.server 8765`, then open `http://localhost:8765/index.html` (same config in `.claude/launch.json`).
- The only external dependency is Web fonts (Google Fonts). There is no server or DB; persistence is the browser's `localStorage`.

## 3. Script load order and dependencies

Order matters: later files use globals from earlier ones.

```
Game   (index.html) : rules → units → masters → common → engine → cpu → cutin → fx → game-ui   (+ css/cutin.css)
Editor (editor.html): rules → units → masters → common → cutin → editor → sim → editor-sim   (+ css/cutin.css)
Worker (sim-worker.js / balance-worker.js, importScripts): rules → units → masters → common → engine → cpu → sim
Balance page (balance.html): rules → units → masters → common → balance (no engine; matches run in the workers)
```

- `engine.js` calls `reloadUnits()` at load time, so `loadUnits` from `common.js` and `DEFAULT_UNITS` from `units.js` must already exist.
- `engine.js` calls `render()` and `cpu.js` calls `fxBusy()`; both are defined in later files but are resolved at run time, so this is fine.
- When adding a new `.js` file, put its `<script>` after everything it depends on.

## 4. Data model

### 4.1 Character ("servant") definition — `DEFAULT_UNITS[i]` / `UNITS[i]`
```
{ id, name, cls, traits?:string[], cost, hp,   // traits = 属性 (multiple, deduped by normTraits; used by atkTrait/defTrait). Omitted from export when empty. Read at runtime via traitsOf(u)
  fit?: { face:{x,y,z}, card:{x,y,z}, np:{x,y,z}, cut:{x,y,z} },   // image framing set in the editor (x/y = object-position %, z = zoom %, 100–300). Defaults in FIT_DEF (common.js); omitted from export when default. Applied by unitImg() via fitStyle()
                                         // np = the close-up face inside the cut-in band (background-position x/y %, z = image width %, 60–300 via fitRange); used by cutinStageHTML, not fitStyle
                                         // cut = the cut-in's standing art on the right: x = shift right (% of stage width, ±30), y = shift down (% of stage height, ±30), z = size % (60–160). For art whose head hits the top
                                         // images are NOT data: img/units/{id}.webp (face) and {id}_card.webp (card, optional)
                                         // card chain: {id}_card → {id} → card.webp / face chain: {id} → face.webp (see imgCandidates)
  link?: string,   // character-setting page (http/https only, normLink). Shown as a button at the bottom of unitDetailHTML; opens in a new tab after a confirm modal (UI.linkAsk; "今後は確認しない" / header button toggles localStorage `pencilduel.linkConfirm`='0')
  lines: { start, attack, extra, damage, skill, np, npDamage, defeat, win },  // each string[] (LINE_KEYS)
  faces: [ {acts:1|2|3, pre:Cmd, post:Cmd} ×6 ],   // pencil faces 1–6. pre = before ascension / post = after
                                                   // acts is IGNORED while RULES.actsTable is set (the default)
  skills:[ {name, eff:Eff[], pick?:'ally'|'other'|'enemy'|'any', line?:string[]} ×3 ],   // other = an ally other than the user (skillPickOk / skillCands; skillUsable is false when nobody can be picked)
    // skill 3 is usable only after ascension. line = skill-specific speech, replaces lines.skill
  ult:   { name, ruby?, br?:number, c:'R'|'B'|'G', eff:Eff[], pick?:'ally'|'other'|'enemy'|'any' } }   // br = cut-in line break: unset = auto, 0 = one line, n = break after n characters (editor: 改行位置 chips under the ult; validateUnits warns when n ≥ name length)   // Noble Phantasm (ultimate). pick = same as a skill's: needed for `t:'picked'` effects (単体の味方への補助宝具など). The ult button then waits for a target click (`G.pending={uid,ult:true}`, `startUlt(u,picked)` → `G.ultPick` → `resolveUlt`); `canUlt` is false when no candidate exists. Extra target `ally_other` (味方全体・自分以外) works in skill / ult / special
```
- `wip?: true` (servants and masters; 制作中): set by the editor's 制作中 checkbox (`wipIn` in editor.js). `unitsToJS` / `mastersToJS` (common.js) skip entries with `wip`, so "js書き出し" leaves them out; "apply to game", the JSON exports and the draft still include them. Kept by `normalizeUnit` / `normalizeMaster`.
- `condLines?: [{key:LINE_KEYS key, who:'other'|'self'|'ally'|'enemy' (LINE_WHO), cond:Cond, lines:string[]}]` (条件つきセリフ; `normCondLine` in common.js, exported by `unitsToJS`, edited in the editor's 「条件つきセリフ」 section via `condIn`). `say(u,key,{other})` → `condLineFor(u,key,other)` (engine.js) uses the first entry whose `key` matches and whose condition holds (`other` = the scene's counterpart: attack target / attacker / skill target / enemy front unit at start; `ally` = another alive ally; `enemy` = any alive enemy, or the whole enemy party once all are down), else falls back to `lines[key]`. Skill/face `line` (own) wins over both. `COND_KINDS` also has `id` (character id, `condOk`: `s.def===v`), usable on effects too.
- Any `Cmd` may carry `line?:string[]` (face-specific speech): on an attack it replaces `lines.attack`/`extra`; on a no-damage special action or the ascension face it is said only when set. Not used when the command was copied from another servant (`cmd.from`). Picked via `say(u,key,{own})` → `pickLine(d,key,own)`.
- `Cmd`: `{c:'R'|'B'|'G', dmg, np, star, eff?:Eff[]}` (optional `eff`, e.g. self-cleanse; applied **after** the attack by default; `normCmd` only keeps it when non-empty) / `{c:'W', label, eff:Eff[], dmg, np, star}` (special action; with `dmg>0` it is also a colorless attack that does not count toward chains — `eff` is applied **before** the attack by default) / `{c:'ASC'}` (ascension face; allowed only in `pre`). R = Buster, B = Arts, G = Quick.
- `Eff`: `{k:effectKind, t:target, v:value, turns?, times?, chance?, color?, trait?, at?:'pre'|'post', max?:true, text?}` (`trait` only for effects with `FX[k].trait`: `atkTrait` / `defTrait`; required there. `max` only for `FX[k].maxOk` (`dmg`, `selfDmg`): the value becomes the target's max HP and ignores modifiers / `nullUnder` ("軽減不可"), read via `effVal(e,t)`; editor checkbox "最大HP". `text` only for `desc`)
  - `cond?:{k,v?,not?}` (any effect except `noTgt` ones; `COND_KINDS` in rules.js, `normCond` / `condText` in common.js, `condOk(c,subject)` in engine.js): the effect only works against a unit that meets the condition. `k` = `trait` (v = 属性) / `cls` (v = class) / `fx` (v = FX key, `'*debuff'` or `'*buff'`) / `hpBelow` / `hpAbove` (v = %) / `npFull`; `not:true` inverts. **Who is checked depends on the kind**: effects with `FX[k].condUse` (`atk`, `atkDown`, `def`, `defDown`) are copied onto the runtime fx with `cond` and checked at damage time against the opposing unit (`modsC` in `dmgMods`; attacker's `atk` looks at the target, the defender's `def` looks at the attacker — so "魅了状態の敵から受けるダメージ-x" = `def` + `cond:{k:'fx',v:'charm'}`). All other effects are checked in `applyEffects` against each target when applied (misses are skipped with a log line); a conditional ultimate `dmg` hits only matching targets (`resolveUlt`). The CPU (`cpuEffScore`) filters targets / needs a matching enemy. Editor: `condIn` in `effRow` (`data-act="condKind"`)
  - `sure?:true` (lasting effects only; dropped by `normEff` for instant / `noTgt` ones; editor checkbox 「解除・無効不可」): the runtime fx is not blocked by 強化無効/弱体無効/精神異常無効 (`applyOne0` skips `immuneTo`) and survives `cleanse` / `cleanseMental` / `strip`; it still ends by `turns` / `times`. Shown as ［解除・無効不可］ in `fxText`.
  - `FX[k].noTgt` (`multiHit`, `desc`): no target / chance / timing; `applyEffects` skips them.
  - `desc` (説明文): flavor only. When an effect list contains one, `effLines` / `effsText` (common.js) show only its text instead of the other effects' descriptions (skill/ult tooltips, detail views, skill panel, editor preview).
  - `at` (commands and ultimates only; ignored with a warning on skills and on `dmg`): apply before / after the attack. Unset = default from `EFF_AT_DEFAULT` (rules.js): special action → before, R/B/G command → after, ultimate → array order. Engine: `splitEffs` (commands) and `ultEffOrder` (ultimates: `pre` effects → array order of `dmg` and unset effects → `post` effects). Editor: the "タイミング" select in `effRow` (`effAtSel`).
  - `k` is a key of `FX` in `rules.js`. `t` is a key of `TARGETS`; the allowed targets depend on where the effect lives (`TGT_BY_CTX`: skill / ult / special).
  - `chance` = succeeds on a roll ≤ N (1–5). `color` only applies to effects with `FX[k].color` (`atk`, `onAtkStar`, `onAtkNp`). Effects with `FX[k].only` are restricted to that place (`dmg` → ultimate, `copyRoll` → special action).
  - A unit without an ascension face (e.g. Mash) may leave skill 3 empty; validation skips it.
  - A lasting effect with neither `turns` nor `times` lasts forever (validation warns).
- **`normalizeUnit()` drops unknown fields.** If you add a new field to characters, follow the whole procedure in §7.

### 4.2 Runtime unit — `makeUnit()` (engine.js)
`{uid:'p{pid}u{idx}', pid, idx, def:<character id>, hp, np, asc, out, used:[bool×3], fx:[], face}`
- `fx[]` holds active effects `{k,v,color,turns,times,owner}`. `owner` is the player who applied it; its `turns` drops by 1 at the start of that player's turn.
- Look up the definition with `D(u.def)` and a unit by uid with `U(uid)`.

### 4.3 Rule constants — `RULES` (rules.js)
`costCap:10, partyMax:3, actionsMax:3, actsTable:[0,1,1,3,2,2], gaugeOnHit:10, gaugeMax:100, ultCost:100, chainR:30, chainB:20, chainG:10, critDmg:30, critDmgR:60, dot:20, dotTiming:'current'|'all'`.
- `RULESETS.team.secondBonus`: the second player's first turn (`G.turn===2`) gives every servant +1 max actions (applied in `rollActs`; still capped at 3 total actions). Measured 6000 random 3v3 games, hard vs hard: first-player win rate 55.1% → 50.7%.
- `actsTable`: action count per pencil face (index 0–5 = face 1–6), shared by all units. Set to `null` to use each face's own `acts` instead. Always read it through `faceActs(d, i)`.
- Critical: `critLevel(stars)` → level 0–7 from `CRIT_TABLE`, `critChance(level)` → % (Lv1 10 / Lv2 20 / Lv3 35 / Lv4 50 / Lv5 75 / Lv6 90 / Lv7 100; thresholds at 1/6/11/16/21/26/31 stars).
- `RULESETS` (rules.js) holds per-rule settings: `team` (3 units, d100 crit), `simple` (1 unit, d6 crit via `CRIT_D6_TABLE` / `critNeedD6`, `handicapAsc:2`) `master` (simple + a master per side, `master:true`, see §5.4) and `mteam` (team + master, `mTeam:true`, `costCap:13`, see §5.5). The active one is `G.rule`; read it through `ruleset()` (engine.js). Party size comes from `ruleset().partyMax`, not `RULES`.
- `dot` is only the fallback damage for poison/burn effects whose value is 0 (old data).

## 5. Game flow (`G.phase`)

```
mode → setup (P1 party → P2 party) → [startGame: decide who goes first] → turns repeat → over
turn: actRoll → skill → action → target → end → (endPhase → swap turn → actRoll)
      └ using an ultimate goes skill → target (skips the action phase)
```
| phase | What happens | Main ACTIONS |
|---|---|---|
| `mode` | Mode select (vs CPU / 2-player) | `chooseMode` |
| `setup` | Party building (total cost ≤ 10, up to 3 units). On the CPU's side "おまかせ" has two buttons: `setupCpu {how:'same'}` (same cost as the opponent; team: same total cost and size, nearest if impossible, `setupMsg` says so) and `{how:'random'}` (= `setupRandom`). Master rules add `setupRandom {only:'svt'}` (keep the master) / `{only:'master'}` (keep the servants; team: a master that fits the remaining cost). "← 戻る": P2 → P1 (`setupBack`, picks are kept), P1 → mode screen (`restart`). Each roster tile has an ⓘ (`.tinfo`, `data-ui="sinfo"` → `UI.sinfo` → `sinfoModalHTML`) | `setupToggle` `setupRandom` `setupCpu` `setupBack` `setupConfirm` |
| `actRoll` | ② Each unit rolls its max action count from `actsTable` (0 is possible); +1 per knocked-out (戦闘不能) ally, −1 with fear, capped at 3. **Actions must be used up**: the total must equal `requiredAlloc()` = min(3, sum of max actions); `confirmAlloc` / `setAlloc` refuse anything else and the 決定 button stays disabled. Damage resolution (`resolveDamage`) in brief: `resolveCommand` per command in order → three same-color commands trigger a chain (R: damage +30 / B: acting units' NP +20 / G: 10 stars generated) → three actions by the same character trigger a Brave Chain (extra attack). There are no class matchups.

### 5.1 Rule source: 泥ペンサバ "Team Battle" rules

The rules follow the 泥ペンサバ wiki's チームバトルルール (3v3, total cost 10), an arrangement of the official Fate/Grand Order -SUMMON PENCIL SERVANT-, **without class matchups**. When a request says "match the rules", this is the reference.

Per command, `resolveCommand` does, in order:
1. Base damage from the face.
2. Skill modifiers via `dmgMods()`: own `atk` (color-filtered) − `atkDown` + target `defDown` − target `def` (skipped if the attacker has `ignoreDef`). Floors at 0.
3. Buster Chain +30.
4. Critical step (only if the player holds stars; never on extra attacks or ultimates): roll 1d100 ≤ `critChance(critLevel(stars) + critRoll)`. On success: damage + 30 (Buster + 60) + `critPow` total + color buffs again (color buffs count double), and NP gain / star generation ×2.
5. Final damage, unless blocked by `invul` / `evade` (`blocked()`). Overkill (target already knocked out): NP / stars ×2. Overkill and critical **stack** (×4).

The command's own `eff` is split by `splitEffs`: "before" effects run before step 1, "after" effects after step 5 (see `at` in §4.1). Ultimates apply their effects in `ultEffOrder` (before → array order → after).

Extra attack (Brave Chain): no modifiers, no critical, but evade/invul still apply.
Damage over time (`endPhase`): ignores atk/def, invul, evade and crits; blocked by `debuffImmune`. Poison and burn each don't stack (the highest value applies); `spread` doubles burn.

### 5.2 Simple rule — シンプルルール (`G.rule==='simple'`)

Chosen on the mode screen (`setRule`, plus `toggleHandicap`; both kept by `restart`/`rematch` via `keepRule()`). Same flow as the team rule (including using the ultimate manually in the skill phase), with:
- 1 servant per side (picking another replaces it). The CPU's "おまかせ（同コスト）" picks the same (or nearest) cost as the opponent.
- Critical: if the player holds stars, roll 1d6; success when roll − `critRoll` ≤ `critNeedD6(stars)` (1–6★: 2, 7–13: 3, 14–29: 5, 30+: certain). Effects of a success are the same as the team rule.
- Win only by knocking out the enemy servant. (The old "NP 100% at turn start = ultimate win" rule was removed.)
- Handicap (`G.handicap`, default ON): `applyHandicap()` in `startGame` ascends the lower-cost side when the cost gap ≥ `handicapAsc`; when the gap ≥ `hcapBonus.gap` (3) it also sets `G.hcap` = that side's servant gets attack damage +`atk` (30, added in `dmgMods`) and NP gained from attacks / hits / Arts chain ×(100+`np`)% (10, `npRate`). Not an fx (cannot be stripped); shown as a chip via `hcapText`. Measured (hard vs hard, all pairs): low side wins gap3 8%→20.4%, gap4 0.2%→3.2%, gap5 0% (with +20 it was 16.5% / 1.6%).

### 5.4 Master rule — マスタールール (`G.rule==='master'`, `masterRule()`)

Simple rule + one master (泥ペンマス) per side. Setup picks a servant (`setupToggle`) and a master (`setupMaster`, `G.mpicks`); CPU "おまかせ（同コスト）" matches servant+master total cost. Handicap uses the total (`sideCost`).
- Master data (`normalizeMaster` in common.js): `{id,name,cls:'マスター',cost,hp,master:true,lines:{support,attack,spell}(MASTER_LINE_KEYS),faces:[{label,eff,line?}×6],spells:[{name,eff,line?}×3]}`. Master speech: `say(m,'support'|'attack'|'spell',{own:face.line|spell.line})`; the editor's master form has a セリフ section plus per-face / per-spell 専用セリフ. Effects use `TGT_BY_CTX.master` (`svt` 自軍サーヴァント, `self` the master, `ally_all` incl. master, `enemy_all` (enemy servants only, labelled 敵サーヴァント全体 via `mTLabel`), `enemy_both` (敵全体: servants + enemy master; `dmg` is split into `enemy_all` + `enemy_master` in `masterEffects` so the master can still be guarded), `ally_svt` 選んだ自軍1騎 (all master rules, support and spells; picked like `enemy_svt` via `pickSide` / `supPickSide`), `enemy_svt` 選んだ敵1体, `enemy_master`, `master` stars). `enemy_svt` needs a pick: `G.spellPick={i,now?,use?,sup?,side}` waits for a click on an enemy servant (`pickSide` / `pickOk` / `pickCands`); support faces roll first, then `masterSupportPick` (cannot be cancelled), spells go through `masterSpell` / `masterSpellUse` with `uid`. `dmg` is allowed there as fixed damage (`fixedHit`). `D()` looks up `UNITS` then `MASTERS`.
- Runtime master: `makeMaster()` → `G.players[pid].master` (uid `p{pid}m`, same shape as a unit so fx/damage code is shared). It is **not** in `party`/`alive()`/`ALL()`; use `ALLM()` / `U()` / `masterOf(pid)`. `m.out` = 瀕死. Damage to a master goes through `dealDamage` → `masterHit` (at HP 0: 瀕死, own servant takes the master's max HP as damage).
- Flow: `actRoll → master → skill → …`. `G.phase==='master'` (once per turn, `G.mastered`): `masterSupport` (roll a face, effects get `tmp` and are removed in `endPhase` = this turn only), `masterAttack {to:'master'|'svt'}` (cost × `masterAtk.master`(20) / `.svt`(10), blocked by the target master's `evac`), `masterSpell` (declare: `P.spell='decl'`, skip to `endPhase`; next master phase `masterSpellUse {i}`) or `masterSpell {now,i}` (pay `spellNowStars`=16★, no skip), `masterEvac` (`P.evac` until that player's next `beginTurn`). 令呪 needs ≥1 action this turn (`canDeclareSpell`), once per game (`P.spell`).
- `G.phase==='guard'` (actor = the defender, `actor()` in cpu.js): `G.guard.kind==='spell'` → master-on-master attack can be voided with the defender's unused 令呪; `'svt'` → a servant attack (or single-target ult) aimed at the enemy master (`masterTargetable()`, not while taunt) lets the defender take it on the servant or the master (`guard {to}`).
- Enemy-all ult damage also hits the enemy master unless evacuated (no invul/evade). Ally-all effects also reach the own master.
- Action count: +1 from `G.turn>=lateBonus` (6 = 3rd round, second player) and +1 after a turn with 0 actions (`P.zeroNext`).
- Non-damage ult (no `dmg` effect): used in the skill phase immediately, costs one allocated action, `G.ultDone`, then normal action phase.
- CPU: `cpuMaster` / `cpuGuard` (cpu.js); it never aims servant attacks at the master (the defender would pick the better side anyway). Log phase numbers go through `PN()`.
- Spell state: `P.spellLeft` (画 left), `P.spellUsed[i]`, `P.spell==='decl'` (master rule declaration only). `canGuardSpell(pid)` / `canDeclareSpell()`. Support/spell effects go through `masterEffects()`, which turns `dmg` on `enemy_master` into a `guard` (kind `spell`) when the defender can still spend a 画.

UI notes: in the master rule (not mteam) the master is drawn as a card beside the servant (`masterCardHTML`, `.svts.withm`); mteam keeps the `.mchip`. Every `.svt` carries a `<i class="glow gl-…">` frame (`glowHTML`): green = evade/invul, blue = buff, red = debuff, cycling green→blue→red when several apply (phase synced via `PULSES`). On ≤860px the NP gauge label (`.npl`) is hidden.

### 5.5 Master team battle — マスターチームバトル (`G.rule==='mteam'`, `mTeam()`)

`RULESETS.mteam`: team rule (3 servants, d100 crit, KO bonus) + a master, total cost ≤ `costCap` 13 **including the master** (`costCap()` / `mcost(pid)` in setup, `setupMaster` refuses an over-cap master; CPU おまかせ enumerates master × servant combos). Everything in §5.4 applies except:
- Master phase is only `masterSupport` and `masterSpell {i}` (`masterAttack` / `masterEvac` are refused). 令呪: `spells` = 3 画, each effect once (`P.spellUsed`), used immediately at the cost of one allocated action; unusable when any alive servant rolled 0 actions (`canDeclareSpell`). Guarding with a 画 against master-targeted damage still works.
- **Master cost bonus** (`RULESETS.mteam.costBonus = {base:3, atk:5, hp:50}`): every own servant gets `(masterCost-3)×5` attack damage and `(masterCost-3)×50` max HP (negative for masters cheaper than 3). It is **not an fx**: `costBonus(u)` is added in `dmgMods` (attack sum) and `maxHp()`, and `startGame` sets the starting HP to `maxHp`, so strip/cleanse/`atkVs` never touch it. Shown as a chip (`costChip` in game-ui) and one log line at start. Measured with skill-less masters of cost 0–5 (3v3, total cost 13): win rate flat within ±3% (without it cost 0 = 75%, cost 5 = 22%). The 3 only works with servants' total cost = 13 − master cost. Shirou's 無限の剣製 was tuned with this: all-enemy dmg 50 + atkDown 15 (it was 150/30 and made him ~70%).
- Masters cannot be targeted by servant attacks (`masterTargetable()` → null), are not hit by enemy-all ults, and ignore debuffs (`applyOne`). Ally-all buffs still reach them.
- 令呪 with a `svt` (自軍サーヴァント) effect target **one chosen servant** in this rule (`spellPicks(s)`): `masterSpell {i}` without `uid` sets `G.spellPick` and waits for a click on an own servant (`cardClick` → `masterSpell {i,uid}`; `cancelPick` clears it); the action and 画 are spent only after the pick. `resolveTargets('svt', picked)` returns just the picked unit. Display text via `spellTgt` / `spellText`. CPU (`spellBest` in `cpuMaster`) scores each spell × each ally and passes `uid`. 補助 effects with `svt` still hit all own servants.

## 6. Design rules (do not break these)

1. **All state lives in `G`, and changes go only through `act(type, payload)` → `ACTIONS[type]`.** `act()` ends by calling `render()`. Humans, the CPU, and (future) online play are meant to share this path, so never mutate `G` directly outside `ACTIONS`.
2. **Always re-validate rules inside `ACTIONS`** (phase, turn, already used, etc.). Merely `disabled`-ing a button in the UI is not enough.
3. **UI-only state belongs in `UI` (game-ui.js)**, not in `G`.
4. **`render()` rebuilds `#app` from scratch every time**, through `setHTML(el, html)` (common.js), which moves already-loaded `<img>` elements with the same `src` + class + style from the old DOM into the new one, so portraits do not flicker or get re-decoded on every phase change (`.mc-o` / `.mc-i` are matched without style). CSS animations restart whenever an element is rebuilt or moved, so the magic circle spins via the Web Animations API (`syncMagicCircle` in game-ui.js, `startTime=0` so the angle depends only on the document clock) and the NP pulses (`.gauge.np.full i`, `.sk.np.ready`) get a clock-based negative `animation-delay` from `syncPulses`; both run at the end of `render()`. Do not put infinite CSS animations on elements that `render()` rebuilds without doing the same. Use `setHTML` / `replaceHTML` instead of `innerHTML` / `replaceWith` when redrawing anything with images (`redrawSvt`, `redrawLane`, `redrawRoster` do). Image URLs that failed once go into `IMG_BAD` and are skipped by `imgCandidates` from then on (so a missing `{id}_card.webp` is not re-requested on every render). Do not add `loading="lazy"` to these images (it causes a blank frame on each re-render). Events are delegated on `document` (`data-a` = game action, `data-ui` = UI action; the editor uses `data-act` / `data-p`). Do not attach listeners directly to elements.
5. **Effects go through `FXQ`** (`fxEmit`/`say`), and `fx.js` plays them on `#fx`. Rule processing does not wait for effects to finish; only the CPU waits via `fxBusy()`.
   - Event types (`ev.t`): `say` (line bubble), `dmg` (damage number / "無効" text), `cutin` (ultimate), `phase` (banner over `.stage`; `big` for turn start / game end), `banner` (chain banners), `roll` (spinning pencil over a portrait, lands on `f`; shows `n` actions or the `cmd` card), `atk` (command card zooms to the stage center and flies to `tgt`), `pop` (text over a portrait, e.g. ascension), `skill` (panel over `.stage` with the skill name, user, picked target and one line per effect; emitted by `doSkill`). Any event may carry `w` to override the wait before the next one (e.g. `say(u,'attack',{w:250})` overlaps the bubble with the attack card). Helpers in engine.js: `say`, `phaseFx`, `rollFx`.
   - Pencil faces (`u.face`, the die / command badge on a portrait) are cleared for every unit in `endPhase` and at the start of `rollActs`, so a card never lingers into the next turn.
   - Knock-outs are shown late on purpose: `retreat()` (engine name for KO) sets `u.out` at once but only queues the uid in `KO_PEND`; `flushKo()` — called at the end of `resolveDamage`, `doSkill` and `endPhase`, before `checkWin` — emits one `ko` event and the `defeat` lines. Until then `stepHold` keeps the card at HP 0 but not darkened, so later attacks (overkill hits, which emit a `dmg` with `over:true`) still play on it. If you add another place that can KO a unit, call `flushKo()` after it.
   - Roll results are hidden until the roll animation lands: `rollFx(uid,f,{keys})` adds keys to `FXHIDE` (`'f:<uid>'` = the portrait's die badge / alloc control, `'r:<idx>'` = that card in the command lane); `reveal()` in fx.js deletes them and redraws. `rollBadge` / `ctlHTML` / `laneHTML` check `FXHIDE`.
   - NP gauge and buffs/debuffs lag the same way: `snapPre()` (start of `act()`) records the displayed state, `syncU(u)` emits `{t:'sync',uid,hp,np,fx}` after a change (deduped by `SYNCED`), and `stepHold` applies it when played. `FXHOLD[uid]={hp,np,fx,out,ko}`; `shown(u)` in `game-ui.js` returns it. When you change NP / `fx` outside `applyOne`, call `syncU(u)`. The 'end' prompt shows "ダメージ処理中" while `fxBusy()` (`UI.defer` re-renders when the queue empties).
   - Displayed HP lags behind `G` on purpose: a `dmg` event carries `hp0` (before), `hp` and `out` (after). `fxEmit` puts the unit into `FXHOLD` at `hp0`; `fx.js` (`stepHold`) advances it per event and redraws only that card (`redrawSvt`); when the unit has no more queued `dmg` events the hold is removed. Cards read HP / knocked-out state via `shown(u)` in `game-ui.js`. Any new code that changes HP through damage must go through `dealDamage` (or emit the same fields) or the bar will jump.
6. Always wrap user data in `esc()` when embedding it in HTML. `log()` messages are rendered as HTML, so insert names via `nm()`/`dn()`.
7. Pull on-screen terms from `TERMS` (rules.js); do not hard-code them.
8. The allocation lane (`allocLaneHTML` / `animateLane` in game-ui.js) flies newly added cards from the servant's portrait; `laneSeen` remembers which cards were already shown so a re-render does not replay it.
9. **Auto-advance (`UI.auto`, header button) only presses buttons that leave no choice**: `autoMove()` in game-ui.js (roll actions, confirm a forced allocation, finish the skill phase when no skill/ultimate is usable, roll each allocated action, attack the only possible target, end the turn). It runs only on human turns, waits for `fxBusy()`, and goes through `act()`. If you add a phase or a button with no choice, add it there too.
10. **The CPU does not know the rules.** Tune strength via `cpuSkillScore` (when to use skills), `cpuBestTarget` (attack target) and `cpuAlloc` (action allocation). `hard`/`expert` (`cpuHard()`) also use `cpuThreatTarget`, hold damage ultimates weaker than `turnPower()` in `cpuUltUser`, allocate actions by expected damage (`cpuAllocEV` / `allocEV`: per-action face averages incl. atk buffs and crit expectation, Buster Chain probability, Brave Chain extra attack, `ASC_VALUE` for an ascension face — so a weak unit's Brave Chain loses to mixing in a unit with roughly twice its per-action damage), and in the team rule time evade/invul skills to enemy ultimates (`cpuGuardScore`: top priority when an enemy has NP 100 and the skill covers the likely target, otherwise held until HP < 35%); `hard` and `expert` pick the attack target with `cpuMcTarget` (a lookahead; `hard` is light: `MC_R_HARD`=4 rollouts × `MC_T_HARD`=10 turns ≈ 30 ms per decision, ~57% vs the old no-lookahead hard in 3v3 same-cost; `expert` is `MC_R_EXPERT`=16 × `MC_T_EXPERT`=40 ≈ 140 ms, ~64%; rollouts count is what matters, turns hardly). `CPU_LOOKAHEAD=false` turns `hard`'s lookahead off (= the old `hard` = `cpuThreatTarget`; **sim.js sets it false** so balance runs stay fast and comparable), and `cpuInRollout` makes `hard` inside a rollout use `cpuThreatTarget` (no nesting). `cpuNextSkill` uses a score threshold of 3 for `hard`/`expert` (2 for `normal`; 2 vs 3 measured equal). In the simple rule `expert` also picks (party of 1) also the skill-phase move with `cpuMcSkill` (it only overrides the `hard` move when it wins by `MC_MARGIN`; in the team rule skill lookahead lowered the win rate, so it is off there). Both go through `cpuMcScores` (Monte Carlo: copies `G`, plays each candidate out `mcRollouts()` times with both sides `hard` (no lookahead), then restores `G` and the FX state — keep that save/restore complete if you add new global engine state). Hand-written skill-timing tweaks (hold atk buffs for Brave Chain, stun only vs NP 100, NP skills early, etc.) were all within ±1–2% of `cpuSkillScore`, so it was left as is. When you add a new effect to `FX`, also add a score to the `switch` in `cpuSkillScore` (otherwise it counts as worth 0).

## 8. Verification

There are no automated tests in the repo, so verify manually in a browser. For rule changes, also consider a quick headless check: load `rules/units/common/engine/cpu` into a Node `vm` context with a no-op `render()`, call `newGame()`, then loop `act(...cpuDecide())` with `G.cpu=[true,true]` for a few hundred games and look for hangs or `NaN` in `G.log`.
- Game: open `index.html` and play one full match each in vs-CPU (easy / normal) and 2-player. Depending on your change, also exercise ultimates, ascension, chains, skill target selection, and knock-outs.
- Balance test: `node` can load `rules/units/common/engine/cpu/sim` into a `vm` context (plus `function render(){}`) and call `simPair(a,b,n,true)` / `simTeam(id,n,UNITS.map(u=>u.id))` directly.

- Confirm there are no console errors in the browser dev tools. To see how a broken `pencilduel.units` behaves, edit `localStorage` directly.

## 9. Known caveats

- `README.md` is practically empty; documentation is consolidated in this file.
- "Apply to game" goes through `localStorage` in the same browser. To share across devices or publish, export `units.js` and replace `js/units.js`.
- `G.phase==='init'` is only set momentarily by `setupConfirm`; `startGame()` → `beginTurn()` immediately moves to `actRoll` (there is no screen for it).
- Many Japanese strings and log messages are hard-coded in the logic (the `log(...)` calls in `engine.js`). The intent is to centralize terms in `TERMS`, but not everything has been moved there.
- The UI text, character data, and log messages in the game itself remain in Japanese; only this document is in English.
- Default roster (9 units, all at official-SPS scale: HP 400–1000, damage 10–140): アルトリア C5, エミヤ C4, ヘラクレス C4, クー・フーリン C3, メドゥーサ C3, メディア C3, 呪腕のハサン C2, 佐々木小次郎 C1, マシュ C0. No placeholder samples remain.
- Terminology: knocked out is `u.out` / `retreat()` in code and shown as `TERMS.out` = 戦闘不能 (never 撤退).
- Terminology: "ascension" in code (`asc`, `ASC`, `ascend`) is shown as `TERMS.asc` = 再臨 (short, for badges/tables) or `TERMS.ascFull` = 霊基再臨 (logs, editor explanations, detail views). Never hard-code 覚醒/再臨 in UI strings.
